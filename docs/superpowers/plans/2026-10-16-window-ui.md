# Window UI 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the window into an attention-first cockpit: grouped sidebar, rich session bar, mirror and
start page, Overview/Activity inspector, ⌘K palette.

**Architecture:** Grouping, filtering, row state text, fuzzy ranking, branch reading and activity rows
are pure functions in VibeCore with unit tests. SwiftUI views in `Sources/VibeSwitcher/MainWindow/` use
them; the window controller wires menus, title, Dock badge and the palette panel.

**Tech Stack:** Swift 6 toolchain, SwiftUI + AppKit (macOS 14+), XCTest, SwiftTerm.

**Spec:** docs/superpowers/specs/2026-10-16-window-ui-design.md

## Global Constraints

- macOS 14 APIs only; no new package dependencies.
- No git process: the branch is read from `.git/HEAD`.
- Never send input to real sessions while verifying; scratch sessions in a temp folder only.
- Copy follows the app's voice: short, plain, sentence case.
- `swift test` stays green after every task; `./build.sh` (or the repo's build script) must build.

## Review Focus

1. A session moving between groups (needs input → working) must keep its selection and keyboard index.
2. Filter text that matches nothing: empty list with "No matches", selection kept off-screen, ⌘J still works.
3. Palette with hundreds of recent-project × preset items: typing stays instant (ranking is O(n·m)).
4. Transcript of many MB: Activity reads only the 256 KB tail, off the main thread.
5. `.git` as a file (worktrees) and detached HEAD show a sensible branch; a missing repo shows none.

### Task 1: Grouping, filtering and row text (VibeCore)

**Files:** Create `Sources/VibeCore/WindowGroups.swift`; Test `Tests/VibeCoreTests/WindowGroupsTests.swift`.

**Produces:**
- `WindowRow.title: String` — custom name › task › host title › host label › project.
- `WindowRow.state(now:) -> RowState` with `text: String`, `since: Date?`, `group: AttentionGroup`.
- `enum AttentionGroup: CaseIterable { needsYou, working, ready, idle }` with `title`.
- `enum WindowGrouping: String { attention, projects }`.
- `WindowGroups.attention(_ sections: [WindowSection]) -> [WindowSection]` (order per spec).
- `WindowGroups.filter(_ sections: [WindowSection], query: String) -> [WindowSection]`.
- `WindowGroups.summary(_ rows: [WindowRow]) -> String` ("2 need you · 3 working", "" when neither).

Tests: classification of every status (paused → idle, starting hosted → working, ended → idle);
ordering within groups (needs-you oldest statusSince first, working earliest startedAt first, ready most
recent first, idle keeps input order); empty groups dropped; filter on title/project/task,
case-insensitive, drops empty sections, blank query is identity; summary wording incl. singular
("1 needs you").

- [ ] Write tests, watch them fail, implement, pass, commit.

### Task 2: Fuzzy matching (VibeCore)

**Files:** Create `Sources/VibeCore/FuzzyMatch.swift`; Test `Tests/VibeCoreTests/FuzzyMatchTests.swift`.

**Produces:** `FuzzyMatch.score(_ query: String, _ candidate: String) -> Int?` (nil = no match; empty
query scores 0) and `FuzzyMatch.rank<T>(_ items: [T], query: String, text: (T) -> String) -> [T]`
(stable for equal scores; empty query returns items unchanged).

Scoring: characters in order, case-insensitive; +1 per character, +8 at a word start (start of string,
after a non-alphanumeric, or a lowercase→uppercase step), +5 when it follows the previous match
directly; minus `candidate.count / 10`.

Tests: in-order required ("gs" in "project-c", not "sg"); word starts win ("ns" ranks "New Session"
above "project-c session"); consecutive beats scattered; shorter wins ties; rank is stable.

- [ ] Write tests, watch them fail, implement, pass, commit.

### Task 3: Branch reader and activity rows (VibeCore)

**Files:** Create `Sources/VibeCore/GitBranch.swift`, `Sources/VibeCore/ActivityFeed.swift`; Tests
`Tests/VibeCoreTests/GitBranchTests.swift`, `Tests/VibeCoreTests/ActivityFeedTests.swift`.

**Produces:**
- `GitBranch.current(in directory: String) -> String?` — walks up to the first `.git`; a file with
  `gitdir: <path>` (relative to its folder) is followed; HEAD `ref: refs/heads/x` → `x`, other `ref:` →
  last component, a hash → 7 characters; nil when no repository or unreadable.
- `ActivityFeed.rows(_ entries: [TranscriptEntry], limit: Int) -> [TranscriptEntry]` — drops
  `.toolResult` entries (their call was before the tail), keeps the last `limit`.

Tests (temp folders): plain repo, subfolder of repo, detached HEAD, worktree `.git` file with relative
gitdir, no repo; activity drops orphan results and keeps the newest `limit`.

- [ ] Write tests, watch them fail, implement, pass, commit.
