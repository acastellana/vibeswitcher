# Chat View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rendered, searchable, live chat view of each agent session with a real composer.

**Architecture:** Parsing (markdown blocks, syntax tokens, line diffs, chat transcript events, timeline
grouping, search, composer text) is pure VibeCore with tests. `ChatModel` (app) reads the transcript tail
incrementally off the main thread and publishes a `ChatLog`; SwiftUI views render it. The middle pane gets a
chat layer over the (still attached) terminal.

**Tech Stack:** Swift, SwiftUI/AppKit (macOS 14), Swift Testing.

**Spec:** docs/superpowers/specs/2026-10-16-chat-view-design.md

## Global Constraints

- No new dependencies. Parsing never on the main thread for transcript files.
- Never send input to real sessions while verifying; composer tests on a scratch window session only.
- Transcript reads are limited to files `TranscriptReader.checkedURL` accepts.

## Review Focus

1. A 20 MB transcript with dozens of base64 screenshots: first paint stays fast (4 MB tail), memory bounded.
2. Tool result arriving in a later read than its call (long-running command): the row completes.
3. Composer text containing ESC / bracketed-paste terminators can't inject terminal sequences.
4. Switching sessions quickly: no stale chat from the previous session, no leaked polling.
5. Markdown edge cases: unterminated code fence, table without leading pipes, nested lists, CRLF.

---

### Task 1: Markdown blocks — `Sources/VibeCore/MarkdownBlocks.swift`
`MarkdownBlocks.parse(_ text: String) -> [MDBlock]`; `MDBlock`: `.heading(level, text)`, `.paragraph(text)`,
`.list(ordered: Bool, start: Int, items: [MDListItem])` (`MDListItem { text, depth, checked: Bool? }`),
`.code(language: String?, text)`, `.quote(text)`, `.table(header: [String], alignments: [MDAlign], rows: [[String]])`,
`.rule`. Tests: each block; unterminated fence runs to the end; table with/without outer pipes and alignment row;
nested list depth; CRLF; paragraphs joined across soft line breaks.

### Task 2: Syntax tokens — `Sources/VibeCore/SyntaxHighlight.swift`
`SyntaxHighlight.tokens(_ code: String, language: String?) -> [SyntaxToken]` (`kind: keyword|string|comment|
number|type|plain`, `range: Range<String.Index>` over `code`). Tests: Swift keywords/strings/comments; Python
`#` comments; shell; JSON; unknown language still marks strings/numbers; escaped quotes; tokens never overlap.

### Task 3: Line diff — `Sources/VibeCore/LineDiff.swift`
`LineDiff.lines(old:new:) -> [DiffLine]` (`kind: same|removed|added`, `text`), `LineDiff.hunks(_:context:) ->
[[DiffLine]]` (`.gap(n)` markers between hunks), big inputs (> 3000 lines each) fall back to all removed + added.
Tests: insertion, deletion, replacement, unchanged, context trimming and gaps.

### Task 4: Chat transcript reader — `Sources/VibeCore/ChatTranscript.swift`
`ChatReader.read(_ data: Data, format:) -> (events: [ChatEvent], consumed: Int)`; `ChatEvent`: `.entry(ChatEntry)`
or `.result(toolID, ChatResult)`. `ChatEntry { id, at, kind }`, kind `.prompt(text, images)`, `.reply(text)`,
`.tool(ChatTool)`; `ChatTool { id, name, title, detail: ToolDetail, result: ChatResult? }`; `ToolDetail`:
`.command(String)`, `.edit(path, [(old, new)])`, `.write(path, content)`, `.read(path)`, `.patch(String)`,
`.questions([ChatQuestion])`, `.agent(description, prompt)`, `.fields([(String, String)])`;
`ChatResult { output, truncated, failed, at, images: [ChatImage] }`; `ChatImage { mediaType, data }`.
`ChatLog` (value type): `apply(_ events:)` appends entries, completes tools by id (also later results), keeps
`prompts` for history. Tests: Claude user/assistant/tool_use/tool_result (text and image content), injected text
skipped, thinking skipped, sidechain skipped, Edit/MultiEdit/Write/Bash/AskUserQuestion details, Codex message /
function_call / output / apply_patch, result in a later apply, duration computed.

### Task 5: Timeline, away marker, search, composer text — `Sources/VibeCore/ChatTimeline.swift`
`ChatTimeline.items(_ entries:, newAfter: String?) -> [ChatItem]` (`.prompt`, `.reply`, `.tools([ChatTool])`,
`.newMarker(summary)`); `ChatTimeline.summary([ChatTool]) -> String`; `ChatSearch.matches(_ items:, query:) ->
[String]` (item ids); `ComposerText.writes(_ text:, bracketed: Bool) -> [HostInput.Write]`. Tests: grouping of
consecutive tools, summary wording/plurals/failures, marker placement and its summary, search across kinds
(case-insensitive), composer strips ESC and other controls, keeps newlines only when bracketed, Enter after 60 ms.

### Task 6: ChatModel + ChatView rendering — app
`MainWindow/Chat/ChatModel.swift`, `ChatView.swift`, `MarkdownView.swift`, `CodeBlockView.swift`,
`ToolGroupView.swift`, `ImageViewer.swift`. Incremental tail reads, "Load earlier", 1 s polling while shown,
working/needs-you rows, away marker using last-seen ids (UserDefaults `chatSeen`), jump to latest.

### Task 7: Middle-pane switch, composer, search
Session bar Terminal|Chat control; ⌥⌘1/⌥⌘2; chat layer over the pane; composer (`ComposerView.swift`, NSTextView
based: ↩ / ⇧↩ / ↑ history / image paste / file drop); ⌘F search bar; Terminal sessions read-only composer
with Move; transcript path kept for ended window sessions.

### Task 8: Verify, README, review
Captures on scratch sessions (chat of a scratch Claude, composer send into a scratch window session), README,
full suite, fresh reviewer, fixes.
